# Sont

VPN-клиент для Windows, macOS и Linux, работающий по ключу-подписке от стороннего
провайдера. Состоит из привилегированного демона-оркестратора, который владеет
соединением, и непривилегированных клиентов в сеансе пользователя.

## Устройство

```
 сеанс пользователя (без прав)          система (SYSTEM/root)
 ┌───────────────────────┐              ┌──────────────────────────┐
 │ sontd agent  — прокси │◀─ named pipe─│ sontd — служба           │
 │ sontd <cmd>  — CLI    │   /unix sock │  ├ подписки              │
 │ tray (в планах)       │              │  ├ конечный автомат      │
 └───────────────────────┘              │  ├ надзор за ядром       │
                                        │  └ сеть: TUN, маршруты   │
                                        └────────────┬─────────────┘
                                                     │
                                            ┌────────┴────────┐
                                            │ Xray-core       │
                                            │ VLESS, Reality, │
                                            │ XHTTP, VMess…   │
                                            └─────────────────┘
```

Права администратора нужны один раз — при установке службы. Дальше она стартует
вместе с системой, а клиенты работают без привилегий.

### Крейты

| Крейт | Назначение |
|---|---|
| `sont-core` | Доменные типы, общие для демона и клиентов |
| `sont-ipc` | Локальный протокол: named pipe на Windows, unix-сокет на прочих |
| `sont-sub` | Разбор подписок: base64/plain, `vless`, `vmess`, `ss`, `hysteria2`, `tuic` |
| `sont-xray` | Генерация конфигурации ядра и разбор его счётчиков |
| `sont-daemon` | Демон, служба, агент сеанса и CLI |

## Режимы работы

**Туннель** — весь трафик системы через TUN-адаптер. Полный охват, нужны права
администратора (один раз, при установке службы).

**Прокси** — локальные SOCKS и HTTP, о которых приложения узнают из настроек
системы. Прав не требует и не создаёт сетевых адаптеров, но охват неполный:
приложение, не читающее настройки прокси, идёт напрямую. Мимо прокси идёт и
QUIC, которым браузеры пользуются постоянно.

## Инварианты

Это не стилистические предпочтения, а вещи, нарушение которых ломает продукт.

1. **Вся истина — в демоне.** Клиенты не хранят состояния; их падение не роняет
   соединение.
2. **Клиенты не требуют прав администратора.** Всё привилегированное делает
   только служба.
3. **Конфигурация ядра собирается в демоне из типизированных структур.** Сырой
   JSON извне не принимается: у ядра есть исходящие соединения к произвольным
   адресам, а работает оно от имени системы.
4. **Ключ подписки не попадает в логи и диагностику.** На диске он зашифрован
   DPAPI, в интерфейсе показывается маской.
5. **«Не подключено» и «трафик заблокирован» — разные состояния** и различимы в
   модели и в интерфейсе.
6. **Проверка не должна уничтожать то, что проверяет.** Ложный отказ хуже
   отсутствия проверки.

## Сборка

```
cargo build --workspace
cargo test --workspace
```

Ядро Xray в репозиторий не входит: это отдельный проект под MPL-2.0.
Установите `xray.exe`, `geoip.dat`, `geosite.dat` и `wintun.dll` из
[официального релиза](https://github.com/XTLS/Xray-core/releases) в
`C:\ProgramData\Sont\core\`. Рядом с бинарём можно положить файл
`xray.exe.sha256` — тогда контрольная сумма будет проверяться перед запуском.

## Использование

```
sontd service install          # один раз, от администратора
sontd service start
sontd agent install            # автозапуск агента при входе

sontd subscription set         # ключ спрашивается из stdin
sontd servers
sontd mode tunnel              # либо proxy
sontd autoconnect on
sontd connect
sontd check                    # куда на самом деле идёт трафик
```

`check` сравнивает внешний адрес по трём путям — через прокси, через настройки
системы и напрямую — и объясняет результат. Он отвечает на вопрос «VPN точно
работает?» фактами, а не состоянием в интерфейсе.

## Состояние

Работает: разбор подписок, генерация конфигурации, оба режима, надзор за ядром с
восстановлением, служба Windows, агент сеанса, диагностика.

Не сделано: kill-switch, раздельное туннелирование по приложениям, автовыбор
сервера по задержке, tray-приложение, поддержка macOS и Linux проверена только
на уровне компиляции.

## Лицензии зависимостей

Xray-core — MPL-2.0, поставляется отдельно. Wintun — собственная лицензия
WireGuard LLC, распространяется вместе с Xray.
