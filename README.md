# Sont

VPN-клиент для Windows, macOS и Linux, работающий по ключу-подписке от стороннего
провайдера.

Соединением владеет привилегированный демон, живущий системной службой. Клиенты —
CLI и агент в сеансе пользователя — прав администратора не требуют и состояния не
хранят: они отдают команды по локальному каналу и отображают то, что сообщил
демон. Права запрашиваются один раз, при установке службы; дальше она стартует
вместе с системой.

Ядром выбран Xray-core. Причина конкретная: реальные подписки используют VLESS с
транспортом XHTTP, а его upstream sing-box не поддерживает — только сторонние
форки. Дополнительно MPL-2.0 снимает обязательства GPL-3.0. Цена решения: Xray не
умеет TUIC, а маршрутизация по процессам у него работает только на Windows и
Linux.

## Крейты

`sont-core` — доменные типы, общие для демона и клиентов. Секреты обёрнуты в тип,
у которого `Debug` печатает маску: полагаться на дисциплину разработчика здесь
нельзя, одна отладочная печать сливает платный доступ пользователя в лог.

`sont-ipc` — локальный протокол. На Windows named pipe с дескриптором
безопасности, на прочих системах unix-сокет с правами, выставленными до `bind`.
Каждое соединение проходит проверку личности процесса на другом конце.

`sont-sub` — разбор подписок: base64 и открытый текст, ссылки `vless`, `vmess`,
`ss`, `hysteria2`, `tuic`. Сети не касается, поэтому проверяется обычными тестами
на корпусе реальных ссылок.

`sont-xray` — генерация конфигурации ядра и разбор его счётчиков.

`sont-daemon` — конечный автомат соединения, надзор за ядром, служба Windows,
агент сеанса и CLI.

## Режимы работы

**Туннель** направляет через сервер весь трафик системы. Полный охват, но нужен
TUN-адаптер, а значит и права администратора при установке службы.

**Прокси** поднимает локальные SOCKS и HTTP, о которых приложения узнают из
настроек системы. Прав не требует и сетевых адаптеров не создаёт. Охват при этом
неполный, и об этом честно говорится в интерфейсе: приложение, не читающее
настройки прокси, идёт напрямую и не сообщает об этом ни пользователю, ни нам.
Мимо прокси идёт и QUIC, которым браузеры пользуются постоянно.

## Инварианты

Не стилистические предпочтения, а вещи, нарушение которых ломает продукт.

Вся истина живёт в демоне. Клиенты не хранят состояния, и их падение не роняет
соединение.

Клиенты не требуют прав администратора. Всё привилегированное делает только
служба.

Конфигурация ядра собирается в демоне из типизированных структур. Готовый JSON
извне не принимается: у ядра есть исходящие соединения к произвольным адресам, а
работает оно от имени системы.

Ключ подписки не попадает в логи и в диагностику. На диске он зашифрован DPAPI,
в интерфейсе показывается маской.

«Не подключено» и «трафик заблокирован» — разные состояния, различимые в модели и
в интерфейсе. Иначе пользователь видит «отключено» и не понимает, почему нет
интернета.

Проверка не должна уничтожать то, что проверяет. Ложный отказ хуже отсутствия
проверки: он сносит работающее соединение и отправляет искать несуществующую
неисправность.

## Сборка

```
cargo build --workspace
cargo test --workspace
```

Ядро Xray в репозиторий не входит — это отдельный проект под своей лицензией.
Возьмите `xray.exe`, `geoip.dat`, `geosite.dat` и `wintun.dll` из
[официального релиза](https://github.com/XTLS/Xray-core/releases) и положите в
`C:\ProgramData\Sont\core\`. Если рядом с бинарём положить файл
`xray.exe.sha256`, контрольная сумма будет проверяться перед каждым запуском.

## Использование

Установка службы и агента, один раз:

```
sontd service install
sontd service start
sontd agent install
```

Первая команда требует прав администратора, остальные нет.

Дальше обычная работа:

```
sontd subscription set
sontd servers
sontd mode tunnel
sontd autoconnect on
sontd connect
sontd check
```

Ключ подписки команда `subscription set` спрашивает из stdin, чтобы он не оставался
в истории команд оболочки.

`sontd check` сравнивает внешний адрес по трём путям — через прокси, через
настройки системы и напрямую — и объясняет результат. Он отвечает на вопрос «VPN
точно работает?» измерением, а не состоянием в интерфейсе.

## Состояние

Работает: разбор подписок, генерация конфигурации, оба режима, надзор за ядром с
автоматическим восстановлением, служба Windows, агент сеанса, диагностика.

Не сделано: kill-switch, раздельное туннелирование по приложениям, автовыбор
сервера по задержке, tray-приложение. Код для macOS и Linux написан, но проверен
только компиляцией.
